Under the hood

What happens between your request and a playable URL

Every resolve climbs the same ladder, stopping at the first rung that works — most requests never leave rung one.

  1. 01

    Spoofed client, no auth

    Requests YouTube as a standard web/Android client. Resolves the large majority of videos with no session state at all.

  2. 02

    Age-restricted fallback

    If the video needs an age gate cleared, retries with a client tier that can pass it without a signed-in account.

  3. 03

    Geo-bypass retry

    If the block is regional, retries the extraction spoofed as originating from each configured bypass country.

  4. 04

    Cookie fallback (opt-in)

    Only if you've set YT_COOKIES on your deployment — a last resort for the small remainder that need a real session.

Endpoints

Every route below returns JSON except the /play/* routes, which stream bytes directly — point ffmpeg or your player at them.

GET/api/youtube/searchSearch by query, get back ranked results
GET/api/youtube/infoFull metadata for one video id
GET/api/youtube/relatedMore-like-this recommendations for a video id
GET/api/youtube/playlistFlat list of a playlist's videos
GET/api/youtube/streamResolved direct media URL as JSON, for players that fetch it themselves
GET/api/youtube/audioRaw audio format list for a video id
GET/api/youtube/play/audioProxies audio bytes directly — point ffmpeg/pytgcalls at this URL
GET/api/youtube/play/videoProxies video bytes at a given height
GET/api/youtube/play/video/hqProxies the highest-quality video stream available
GET/healthLiveness check for uptime monitors
Access

Open by default, keyed when you want it

Leave API_KEYS empty for a private deployment only your own bot talks to. Set it to require a key on every request.

Open mode

No API_KEYS set — every route above works with no key at all.

curl -s "https://your-host/api/youtube/search?q=lofi"

Key mode

Send it as a header for normal HTTP clients, or as a query param for tools like ffmpeg that can't attach headers.

curl -H "X-API-Key: <key>" ".../api/youtube/search?q=lofi" — or — ".../api/youtube/search?q=lofi&api_key=<key>"
